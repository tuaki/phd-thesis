\chapter*{Conclusion}
\addcontentsline{toc}{chapter}{Conclusion}
\label{chap:conclusion}

This thesis addresses the problem of managing multi-model data in a way that preserves both semantic coherence and practical usefulness across heterogeneous database systems. Starting from the existing categorical foundations for modeling, transformations, and querying, we extended the approach toward the parts that make a multi-model system viable in practice: evolution, automation, workload-aware optimization, and evaluation. The central idea throughout the thesis is that a shared conceptual representation should not erase the differences between individual data models but should instead provide a stable semantic layer from which different logical representations, queries, and adaptations can be derived systematically.

Let us summarize the contributions of this thesis with respect to the research questions formulated in \Cref{sec:research-questions}.

\paragraph{Evolution}
The first main contribution is a unified approach to evolution management. We showed that schema changes in a multi-model system can be described by a common set of atomic operations and then propagated consistently across conceptual schemas, logical schemas, data, and queries. On top of these atomic operations, we defined more user-friendly composite and complex operations that capture higher-level restructuring intent while still remaining reducible to basic propagation steps. This made it possible to formulate evolution as one connected, platform-independent process rather than as a collection of isolated model-specific migrations. An important extension of this work was the propagation to queries, including cases where information capacity decreases and the original query cannot be preserved by a trivial rewrite. In this setting, we also introduced FDepHunter as a supporting tool for obtaining better semantic evidence from data so that ambiguous synchronization decisions can be guided by more reliable functional dependencies instead of purely ad hoc choices.

\paragraph{Self-adaptation}
The second main contribution is the move from reactive propagation to proactive self-adaptation. Before proposing our own solution, we studied workload-aware index selection in heterogeneous systems and showed that existing methods remain strongly tied to the assumption of a fixed logical representation. This observation motivated a broader formulation of the optimization problem---instead of tuning one already chosen schema, the system should search over alternative mappings, embeddings, and redundancies of the same conceptual schema across multiple databases. We therefore defined a finite configuration space based on a state matrix, proposed an automated search process over this space, and implemented it in MM-mapsearch using \acrshort{mcts} guided by learned cost estimation. This contribution shows that self-adaptation in a multi-model setting can be treated as a principled optimization problem over representations, not only over physical structures inside one database.

\paragraph{Benchmarking}
The third contribution concerns the practical conditions under which such ideas can actually be tested and deployed. Through TransforMMer, we addressed the lack of realistic multi-model benchmarks by showing how a real dataset can be transformed into multiple semantically equivalent multi-model representations together with related queries. This gives the framework a reproducible way to evaluate querying, evolution, and self-adaptation under varied workloads and model combinations.

\paragraph{Alternative approaches}
At the same time, DortDB explored the limits of the overall research direction. While the main line of this thesis relies on explicit schemas and mappings, DortDB showed that there is also value in a more lightweight approach centered on language interoperability---heterogeneous sources can be queried by recursively combining established languages and translating them into a shared algebraic layer.
\\

\noindent Overall, the thesis demonstrates that multi-model data management can be approached as one coherent problem spanning semantic modeling, query processing, evolution, and optimization. The proposed framework establishes a consistent architecture in which these parts fit together---a conceptual schema provides the semantic anchor, mappings connect it to concrete logical representations, queries can be formulated and optimized across models, changes can be propagated through the whole stack, and workloads can eventually drive automatic reconfiguration. In this sense, the thesis moves the research agenda from isolated multi-model techniques toward an integrated and increasingly automated system.

\subsubsection{Future Work}

The remaining work follows directly from the research challenges identified in the previous chapters. Some of these questions are only partially addressed by the current results, while the rest remain mostly open.

\questionRef{ep}{data-propagation} -- Propagation to data is still incomplete. The current framework can preserve consistency by transforming data to the common representation of the new schema, but it does not yet provide a general way to perform the same changes in place through efficient sequences of \acrshort{ddl} and \acrshort{dml} statements. A major next step is therefore to synthesize database-level migration plans that keep the guarantees of the current approach while avoiding full rematerialization whenever possible. The general idea is to define a set of model-independent operations over data, compile the \acrshort{smo}s into a sequence of such operations, optimize it, and then translate it into a model-specific \acrshort{ddl} and \acrshort{dml} sequence.

\questionRef{ep}{evolution-inference} -- At the moment, we cannot infer changes in the schema of the data. Although we can infer its new schema, we are still missing the ability to compare it with the old schema and detect the actual changes. This is a crucial step for enabling bottom-up evolution, where changes originate in the data rather than in the conceptual schema. We plan to use existing approaches to graph and tree diffing~\citep{gao2010survey, chawathe1996change} to find the smallest sequence of \acrshort{smo}s that explains the difference. Additionally, we might develop a cost model that takes into account the cost of propagating the changes and/or the plausibility of the changes based on semantic evidence in the data.

\questionRef{ep}{migration-strategy} -- Migration strategy selection remains only partially resolved. Currently, we consider only eager propagation, even though there are use cases for lazy and hybrid alternatives~\citep{scherzinger2013managing, scherzinger2016nosql}. We intend to first survey decision mechanisms that can choose among them according to data size, workload intensity, redundancy, and the expected cost of query reconstruction and maintenance (e.g.,~\citep{hillenbrand2019migcast, DBLP:conf/icde/HillenbrandSLNK20}). Then we will adapt them to our categorical framework.

\questionRef{sa}{latency-estimation} -- Latency estimation for self-adaptation is only partially solved. We already have learned estimators and plan-based evaluation, but the current approach still depends on materializing candidate configurations to obtain the query plans needed for prediction. Our plan is to extend the open-source implementations of existing database systems with an interface that would allow us to extract the query plans only from metadata instead of fully materialized data.

\questionRef{sa}{workload-prediction} -- We did not explicitly explore workload prediction. The current optimization process reasons about a given weighted workload, but a truly autonomous system should also account for how workloads evolve over time, including periodic patterns, long-term shifts, and short-lived anomalies~\citep{DBLP:conf/sigmod/MaAHMPG18}. Without this predictive layer, the system risks adapting too strongly to the present state and missing more beneficial future configurations.

\questionRef{sa}{richer-state-space} -- The current search space captures only a limited set of design choices (i.e., model assignment, embedding, and cross-model redundancy), all of which are at the logical level. This is already enough to make self-adaptation meaningful, but it does not yet include richer physical design choices such as indexes, materialized views, partitioning, replication, or system-level tuning parameters. There are many existing approaches in this area (see \Cref{vldb_2024:sec:ai4db,dke_2026:chapter:algorithms}); our idea is to combine them with the state-matrix representation.\\

\noindent Taken together, these open directions show that the thesis establishes the conceptual and algorithmic core of the problem, but there is still some work to be done before we can turn it into a fully autonomous and practically scalable system.
